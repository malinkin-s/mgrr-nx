# Настоящие шейдеры игры (Xenos → XenosRecomp → SPIR-V → Vulkan)

Проверка: модели WMB рисуются **оригинальными пиксельными и вершинными шейдерами Xbox 360** (не нашим упрощённым освещением).
Конвейер: `tools/export_scene.py` (сборка «пакета сцены») → `tools/vkview/main.cpp` (Vulkan-рендерер, офлайн, PPM).
Галерея: `x360_work/realshader_gallery.png`, `realshader_props.png`. Это прототип рендерера будущего порта.

## Запуск
```
S=<scratchpad>; $S/venv/bin/python tools/export_scene.py em0200 /tmp/pkg [--yaw 35 --pitch 14 --size 900 --alpha-test --all-meshes --only-key KEY --vs vs_xxx.vso]
clang++ -std=c++17 -O2 -I<Vulkan-Headers>/include tools/vkview/main.cpp -o vkview -lvulkan   # один раз
vkview /tmp/pkg out.ppm
```
`tools/shaders/shaderlib.py`: XenosRecomp→HLSL→DXC SPIR-V по требованию (`x360_work/shaders/hlsl_mgr`, `spv_mgr`), разбор интерфейса шейдера (входы, интерполяторы, константы, сэмплеры).

## Правила, найденные экспериментально
* **PS по ключу материала**: `modelshader` + ключ (второй флаг `b`→`x`, нижний регистр) + `.pso`; покрытие 99.9%. Для 90 проверенных моделей все материалы нашли PS.
* **VS не определяется ключом**: берётся из семейства `vs_*.vso` так, чтобы VS писал все интерполяторы, которые читает PS, а его входы ⊆ атрибутов меша; среди подходящих — с наименьшим числом входов, затем «простой» `vs_vs*` (варианты `a`/`n` только переставляют регистры). Скиннинг: `…w…`.
* **Нормаль/тангент**: ABI XenosRecomp объявляет их `uint4`. Для MGR тангент — UBYTE4N (0..1, VS делает `*2-1`), а w у R11G11B10 всегда 0 → получалась отрицательная яркость (чёрные модели). Решение: spec-константа bit0 = 0, Normal/Tangent подаются как `R32G32B32A32_UINT` с битами float4 (normal в [-1,1], tangent = байты/255, w = tangent_w).
* **Цвет вершин**: порядок байт в памяти A,R,G,B (D3DCOLOR) → исправлено в `wmb.py` (`np.roll`).
* **Константы** (регистры float4): VS c0 View, c4 Proj (z 0..1, RH), c8 ViewProj, c12 ViewInverse, c16 World, c20 WorldView, c40.. палитра костей (3 float4 на кость; пока единичная), c184 fogParam (x·(y+z) → при (1,1e6) тумана нет; при x=0 весь кадр = цвет тумана → чёрный), c195/c199 полусферное освещение. PS c12 ViewInverse, c40.. параметры материала (16 float из `params_ptr`), c61 light_Color, c62 lightpos, c71 ambient_rate_rate, c77 prefogcolor_enhance (w = alpha).
* Сэмплеры по имени→роль привязки материала: `Color_1`=role 0, `cubemap`=role 4, `normalmap`=role 2; остальные (A_Occ, Shadow_Tex…) — белая 1×1; нормали по умолчанию (128,128,255); cube — серая.
* Меши `*_EFD*` (эффектные оболочки, шейдер cnm21) скрыты как состояние-варианты.

## Результат
* 90 моделей (каждая 8-я): 85 получили отрисовку, 83 визуально осмысленны; 4 не открылись из-за старого загрузчика (`ba0066`, `ba0404`, `bh51e0`, `bm51de`: `pgdat` assert — другой контейнер), 1 пустая сцена.
* Проверено на: em0200, em0100, pl0100 (скин, bind-поза), prop-ах `siv/ois/cnm/css/sis`, оружии, персонажах.

## Ограничения / дальше
* Освещение — заглушка (один направленный свет, нет теней и cubemap окружения, фог выключен); реальные значения из рендер-цикла игры не восстановлены.
* Альфа-тест/смешивание не выведены по материалам (флаг `--alpha-test` глобальный; blend=0), прозрачные части рисуются как непрозрачные.
* Кости: единичная палитра; анимации (.mot) не разобраны.
* 10 шейдеров XenosRecomp не конвертирует (частицы и 6 без сэмплеров).
* TextureCube/3D heaps в vkview не заполняются (cube подменён 2D-заглушкой).
