# MGR:R → Nintendo Switch: рамки проекта

Документ фиксирует цели, ограничения и архитектуру. Решения приняты владельцем проекта 2026-10-20.
Если решение надо поменять, правим этот файл и пишем в журнал решений (внизу), а не меняем его молча.

## 1. Цель

**Вертикальный срез:** пролог **R-00** (главное меню → ролики → рядовые враги → Zandatsu → босс Metal Gear RAY → титры главы),
нативный homebrew на Switch, **60 кадров/с** на любом Switch с разгоном.

Порядок: **Switch запускается как можно раньше** (дешевле узнать о проблемах сразу). Linux PC — параллельная цель для отладки; каждая веха с M1 принимается на обеих платформах. Организация репозитория — по мере необходимости, а не заранее.

### Не входит в рамки (non-goals)
- Остальные главы, DLC (Jetstream, Blade Wolf), VR-миссии, кроме тех, что нужны для R-00.
- Сетевые функции, рейтинги, достижения Xbox Live (только заглушки).
- Эмуляция PM4/Xenos на уровне команд GPU (как в Xenia).
- Данные и код PC- и Shield-версий (используем только для справки).
- Сборки под Windows и macOS, моды и улучшения графики сверх оригинала.

## 2. Жёсткие ограничения

| Что | Ограничение |
|---|---|
| Исходник | Только x360-диск MGR:R, TitleID 4B4E080A, default.xex с известным хешем (базовый адрес 0x82000000). Другие ревизии и TU не поддерживаем, пока не решим отдельно. |
| Распространение | Пользователь собирает порт **из своего образа**. В репозитории нет кода игры, её ресурсов и сгенерированного C++ / SPIR-V. Всё генерируется локально. |
| Лицензия | **GPL-3.0**. Основа — rexglue-sdk-nx (BSD-3, производное от Xenia); XenonRecomp и XenosRecomp под MIT. Всё совместимо с GPL-3. |
| Целевое железо | Худший случай — **Erista (v1) с разгоном**: CPU 1785 МГц, 3 ядра для приложения; GPU 921 МГц; 4 ГБ RAM. Режим title takeover (около 3,2 ГБ доступно), Atmosphère. |
| Кадр | **16,6 мс** на худшем железе. Это жёсткое требование: если не укладываемся, снижаем нагрузку (разрешение, тени, частицы, дальность), а не частоту. |
| Тулчейн | C++20, CMake. На PC — clang, Vulkan 1.3. На Switch — libnx и **deko3d**; код игры — clang с заголовками devkitA64 (S0c), остальное и линковка — devkitA64 GCC. |
| Эталон | Поведение и картинка x360 (Xenia и скриншоты с консоли как ориентир). |

## 3. Архитектура

```
 образ x360 (пользователя)
   └─ tools/build-from-iso ── extract ISO → XEX decrypt → XenonRecomp (+наши патчи) → ppc/*.cpp
                          ├─ CPK/DAT → распаковка ресурсов (как есть, без конвертации, где возможно)
                          ├─ шейдеры: XenosRecomp → HLSL → SPIR-V (PC) / GLSL → uam → DKSH (Switch)
                          └─ звук/видео: перекодировка XMA и роликов в форматы, дешёвые для Switch (решить в M3)

 исполняемый файл
   ├─ ppc/ (сгенерированный код игры, big-endian гостевая память)
   ├─ runtime/   ← rexglue-sdk-nx: память (4 ГБ гостевого пространства), потоки, ядро Xbox и XAM (из Xenia), файлы, XMA, слой Horizon
   ├─ gpu/       ← перехват D3D на уровне API (адреса — d3d_entrypoints.json) → RHI
   │    ├─ rhi/vulkan   (PC; из прототипа tools/vkview)
   │    └─ rhi/deko3d   (Switch)
   ├─ hle/       ← патчи точек игры (встроенный D3D, таймеры, пути, качество)
   └─ platform/  ← SDL2 (PC) / libnx (Switch): ввод, окно, аудиовыход, файловая система
```

Принципы:
1. **Перехват на уровне API, а не эмуляция GPU.** Найденные функции D3D (Draw*, Set*, Resolve, Swap, Create*) заменяются нашими реализациями. Если код игры пишет в командный буфер в обход API, патчим это место точечно (`hle/`).
2. **Всё дорогое — во время сборки.** Шейдеры, конвертация форматов, где это допустимо, перекодировка звука и видео. На Switch не должно быть компиляции шейдеров во время игры.
3. **Один RHI на две платформы.** Набор возможностей — по меньшему из двух (deko3d). Bindless-модель XenosRecomp на deko3d отображается в обычные дескрипторы (проверить в M4-спайке).
4. **Гостевая память.** Под hbl `svcMapPhysicalMemory` и `svcMapMemory` в alias не работают (S0). Основной кандидат — приём UnleashedRecomp-NX: окно 4 ГБ из ASLR-региона, страницы из кучи подключаются по требованию через `svcMapProcessCodeMemory` + `svcMapProcessMemory` (нужны syscall-подсказки hbl; проверить на Erista). Запасной — окно внутри кучи (способ F, проверен). Все аллокаторы ядра Xbox реализуем сами. Риск: жёстко прошитые адреса вне выделенных диапазонов (например, MMIO GPU 0x7FC8xxxx) — проверить в M1.

## 4. Вехи

Простые объёмные задачи (заготовки, однотипные заглушки, механические преобразования, тесты) отдаются `agy` (Gemini 3.8 Flash) через `tools/agy_task.sh` в изолированной папке задачи; проектирование, реверс и проверку результата делает Claude. Ничего от agy не попадает в проект без компиляции и проверки.

Каждая веха заканчивается приёмкой. Работа идёт короткими шагами с подтверждением. Рискованные гипотезы проверяются спайками (S*) до основной работы.

| Веха | Содержание | Критерий приёмки |
|---|---|---|
| **S0 Микробенчмарк Switch** | Горячие функции из уже перекомпилированного кода игры (без ядра) + проба гостевой памяти на Horizon; .nro на Erista | Есть «гостевые MIPS» на A57 (штатная частота и 1785 МГц) против PC, и ответ, как разместить 4 ГБ гостевого пространства |
| **M0 Фундамент (минимум)** | Репозиторий (git, whitelist-`.gitignore`, GPL-3, подмодуль `sdk/` = rexglue-sdk-nx); перенос наших данных рекомпиляции (функции, границы, 596 таблиц переходов) в манифест ReXGlue (`game/`); сборка кодогена ReXGlue на хосте; `build-from-iso`; цели Linux и Switch в CMake | Из ISO одной командой собираются Linux-бинарник и .nro; кода игры в репозитории нет |
| **M1 Загрузка (PC + Switch)** | Ядро и XAM из SDK (покрывают все 201 импорт MGR: 189 реализованы, 12 заглушек), файлы из media/, потоки. На PC сначала со штатной эмуляцией GPU ReXGlue (как в xbox360-nx) — это даёт первую картинку до своего рендерера; на Switch — без графики | Игра доходит до цикла `Swap` и крутится 10 минут без падений на PC и на Erista |
| **S1 Замер кадра на Switch** | Время кадра логики игры без графики на Erista (1785 МГц) | Есть замер и решение по 60 кадрам/с (сколько оптимизаций нужно) |
| **M2 Графика** | D3D → RHI: Vulkan (PC) и сразу deko3d (Switch), кэш шейдеров, текстуры, render targets, Resolve | Главное меню и начало R-00 совпадают с эталоном x360 на обеих платформах |
| **M3 Срез** | Ввод, звук (XMA), ролики, сохранения | R-00 проходится целиком на PC и на Erista |
| **M4 60 кадров/с** | Профилирование, оптимизации рекомпилятора, настройки качества | R-00 держит 60 кадров/с на Erista с разгоном (1-й процентиль ≥ 55) |

## 5. Главные риски

| Риск | Чем грозит | Как проверяем / снижаем |
|---|---|---|
| CPU Switch слабее Xenon (плюс перестановка байтов) | 60 кадров/с недостижимы даже без графики | Ранний сигнал в S0, замер в S1; оптимизации рекомпилятора (меньше swap, инлайн), распределение потоков |
| D3D встроен в код игры | Перехвата API недостаточно | Поиск записей в командный буфер и регистры вне D3D-ядра (по `RENDER_STATE_MAP.md`); точечные патчи |
| Гостевые 4 ГБ на Horizon | Рантайм не переносится как есть | Проверить в S0 (проба), окончательно в M1 |
| Bindless и BDA на deko3d | Шейдеры XenosRecomp не ложатся на deko3d | Спайк в начале M2: один шейдер игры на deko3d |
| XMA и ролики на Switch | Декодирование съедает CPU | Перекодировка при сборке; формат выбрать в M3 |
| Ориентир UnleashedRecomp-NX: Sonic Unleashed на Switch — 30 кадров/с при ~400p с разгоном | Цель 60 кадров/с может оказаться недостижимой для MGR | Список оптимизаций — `x360_work/OPTIMIZATIONS.md`; мерить по одной |
| Нагрузка на GPU (Tegra X1 против Xenos + eDRAM) | Не хватает пропускной способности | Динамическое разрешение, упрощение теней и частиц |
| Объём работы | Похожий проект занял у команды больше года | Узкий срез, жёсткие критерии приёмки, non-goals |

## 6. Что уже есть (на 2026-10-20)

- Перекомпиляция: XenonRecomp с патчами, 57 025 функций, 0 предупреждений, тестовая сборка AArch64 проходит (`x360_work/`, `tools/switch_build/`).
